# Lines for sx2-extramapper-mcp, the SX-2 (MSX2+, 6144 KB) with its Extra-Mapper on and SX2RES running.

# The BASIC loader's POKE -1,X copies page 3's subslot to every page of the
# subslot register. Here that is 55h, the RAM of slot 0-1 also in pages 0 and
# 1, under BASIC itself, so line 20's POKE becomes a REM.
patch side1:71 50 4F 4B 45 > 52 45 4D 20

# NB3's search at 8700h looks for a slot register value with RAM in pages 0
# and 1, which does not exist here, where the BIOS and the RAM are both in slot
# 0, in subslots 0 and 1: the first patch skips it. The loader's copies at
# 8732h and 8748h, and NB4's moves at F97Fh, select that value from 87FFh by
# the slot register. The patches write slot 0's subslot register instead: 55h
# for RAM in every page, and 50h, BASIC, after them, in NB3's and NB4's unused
# bytes.
patch side1:472C CD 0E 87 > AF 00 00
patch side1:475C 3A FF 87 D3 A8 > 3E 55 32 FF FF
patch side1:4772 3A FF 87 D3 A8 > 3E 55 32 FF FF
patch side1:4782 F1 D3 A8 FB C9 00 00 00 > F1 3E 50 32 FF FF FB C9
patch side1:ECAD 3A FF 87 D3 A8 > 3E 55 32 FF FF
patch side1:ECF8 F1 D3 A8 FB C3 80 E9 00 00 00 > F1 3E 50 32 FF FF FB C3 80 E9

# The game repeats the search at E980h and keeps the value at E9BCh. Its slot
# register then has RAM in page 1 and the BIOS in page 0: here 54h in slot 0's
# subslot register, which the first patch writes before it jumps past the
# search. The search's bytes then hold two routines: at E98Dh, select 54h, EI
# and RET, and at E994h, select 54h and RET.
patch side1:E502 DB A8 F5 E6 F0 CD 91 E9 28 1F 3C 18 F8 47 D3 A8 21 00 00 CD A4 E9 > 3E 54 32 FF FF FB C3 BD E9 3E 54 32 FF FF FB C9 3E 54 32 FF FF C9

# The game swaps the RAM into page 0 from E9BCh by the slot register, with the

# write 55h, RAM in every page, and 54h back, by the routines at E98Dh and

# Nothing loads after the snapshot: the load ends at the tape's end, as on
# sx2-noexp0. With the tape service, T0 would share page 0 of slot 0-1 with the
# game's own RAM there, so the image goes without it.
service no

# Right after the restore the game writes RET into H.KEYI, over the image's
# CALL resb, and then points it to a routine of its own, so SX2RES got one
# call. That routine returns to the BIOS's interrupt routine.
# The BIOS's interrupt routine still calls H.TIMI after it, so H.TIMI calls
# resb at FD29h too: CALL 0FD29h / RET.
patch page3:3D9F C9 8B E4 40 C9 > CD 29 FD C9 C9
