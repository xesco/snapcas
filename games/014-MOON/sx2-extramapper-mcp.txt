# Lines for sx2-extramapper-mcp, the SX-2 (MSX2+, 6144 KB) with its Extra-Mapper on
# and SX2RES running.

# The capture runs on sx2-extramapper-noram30, the SX-2 with its Extra-Mapper on and
# without the 2048 KB mapper in slot 3-0. On sx2-extramapper-mcp itself the game
# fails: build.py: the snapshot keeps the RAM page 3-0-0-3.bin in slot 3-0, which
# the machine's resident program holds: the game needs RAM in another slot. `make
# games` wrote this line.
capture sx2-extramapper-noram30

# After the snapshot the game puts its own routines into H.KEYI, JP 5C46h copied
# from 5C2Eh and JP 61EEh written with LD HL,61EEh at 61CCh, over the image's
# call of SX2RES. They need no wrapper: each saves the hook that it replaces, at
# 5C31h and 61BCh, and calls it, so the call runs from them while the hook that
# they save holds one. To turn its routine off the game copies the hook that it
# saved at 5C31h into H.KEYI with RET first, from 5C36h, and the calls stop. The
# patch makes it write JP FD29h there instead, a jump to the image's resb, which
# calls SX2RES and returns, as the image's H.KEYI does at the restore. The saved
# hook keeps its first byte: only the game's routine calls the hook, and the
# game saves it again before it puts the routine back.
patch page1:1C36 21 31 5C 36 C9 11 9A > F3 21 29 FD 22 9B FD
patch page1:1C3D FD 01 05 00 F3 ED B0 > 3E C3 32 9A FD FB C9
