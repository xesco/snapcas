# Lines for sx2-extramapper-mcp, the SX-2 (MSX2+, 6144 KB) with its Extra-Mapper on and SX2RES running.

# The game never reads the tape again: the rest of the tape is the next game's.
# It keeps data in page 0's RAM and runs with the BIOS in page 0, in another
# subslot of DOS's mapper's slot, which the tape service's T0 cannot hold.
# Without the tape service the restorer keeps the BIOS there.
service no

# Super MSX's loaders find RAM for pages 0 and 1 by the slot register alone, keep
# the values at FFFDh and FFFEh, and select them later by the slot register
# again. Here the BIOS and the RAM are both in slot 0, in subslots 0 and 1, so
# the patches write slot 0's subslot register instead: 54h for RAM in pages 1
# to 3, 55h for RAM in every page, 50h for BASIC, with SLTTBL's entry for slot 0

# After the snapshot the game puts its own routine into H.KEYI, over the image's
# call of SX2RES, which then stops: JP 4475h copied from 4462h. The image's
# wrapper calls SX2RES and jumps to it.
rescall 4475

# The game installs the wrapper's address instead, FD60h after resb at FD29h, as
# build.txt's resvector gives it.
patch page1:463 75 44 > 60 FD

# To turn its routine off the game fills H.KEYI with RET, from 4465h, and the
# calls stop. The game's routine replaces the BIOS's interrupt routine, so with
# it off the BIOS's routine runs alone. The patch writes JP FD29h there instead,
# a jump to the image's resb, which calls SX2RES and returns, as the image's
# H.KEYI does at the restore.
patch page1:465 21 9A FD 11 9B FD 36 > F3 21 29 FD 22 9B FD
