# The loader's `slots` RAM search finds the RAM in 0-1 and leaves slot 0's
# subslot register at 55h, but its result and BASIC's slot register value are
# both 00h here, where the BIOS and the RAM share slot 0, so each later switch
# by the slot register alone does nothing. The patches skip the search and make
# each use of its stored values a write of slot 0's subslot register instead:
# 55h for RAM in every page, 54h for RAM in pages 1 to 3, 50h for BASIC.

# 3.6 seconds after the end of the load the game clears page 3 from FD9Ah,
# over the image's call of SX2RES. The snapshot comes after that, at 224
# seconds, where the game runs.
snapshot at 224

# The game runs with its interrupts off and no BIOS in page 0, so the image
# has no call of SX2RES from an interrupt. In play E940h clears xx00h..xx6Bh of
# upper pages and E150h clears D7xxh. Put res3 at EF80h and its stack at EFB0h,
# in the unused zeros at EF70h..EFFFh.
rescode EF80
resstack EFB0

# The game tests each key with its routine at ED3Bh, in its title and in play,
# thousands of times a second, and never reads the VDP's status. A routine at
# EFD0h (clear of E150h's clear of D6E1h..DABFh and E940h's clear of xx00h..xx6Bh)
# reads that status and, when its frame flag is set, at most once a frame, calls
# res3 at EF80h on a stack of its own below EFFCh, because the game's stack is
# in page 1, which res3 selects for SX2RES. Then it does the instructions that
# the next patch replaces, PUSH BC / PUSH AF / SRA A, and jumps back to ED3Fh.
patch page3:2FD0 00 00 00 00 00 00 00 00 00 00 > F5 DB 99 07 30 0E ED 73 FE EF
patch page3:2FDA 00 00 00 00 00 00 00 00 00 00 > 31 FC EF CD 80 EF ED 7B FE EF
patch page3:2FE4 00 00 00 00 00 00 00 00 > F1 C5 F5 CB 2F C3 3F ED

# The key routine's first instructions jump to the routine at EFD0h.
patch page3:2D3B C5 F5 CB 2F > C3 D0 EF 00
