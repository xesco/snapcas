# Lines for sx2-extramapper-mcp, the SX-2 (MSX2+, 6144 KB) with its Extra-Mapper on and SX2RES running.

# The game's page 3 has no 158 free bytes from an address xxE1h for the tape
# service's part, and it keeps RAM of its own in page 0, in the Extra-Mapper,
# DOS's mapper. So the mode without a part in page 3, whose T0 needs page 0 of
# DOS's mapper, cannot take it, and the SX-2's other RAM, in slot 3-0, is
# SX2RES's. So the part goes apart. The game draws its menu and the race in a
# buffer from EA00h to FEFFh, which takes every xxE1h below FFE1h. Its entries go
# at FFE1h to FFFAh, over the BIOS's copies of VDP registers 8 to 23 and MINROM:
# the game has its own page 0 and interrupt routine and never calls the BIOS,
# and neither it, the tape service nor SX2RES reads them. Its code block goes at
# FF01h to FF84h, in hooks that hold RET, and sub0 follows it. The game reads and
# writes none of these bytes in its menu or in a race of course A.
service at FFE1 FF01

# The image has no call of SX2RES: the game uses the zeros at FCC9h in page 3,
# where the image's wrapper for the call goes with the tape service, and the
# game's stack is in page 1, where the wrapper leaves the call out. A routine at
# 86D8h, as in Knight Lore's file for this machine, in zeros of page 2 that the
# game leaves alone in a minute of play with keys, uses no BIOS routine. It
# keeps all the registers and the interrupts, selects slot 3's subslot 0 in page
# 1 with slot 3's subslot register, selects slot 3 in page 1 with the slot
# register, and calls SX2RES's entry at 4040h when it starts F5h DBh. Then it
# gives both registers back. At 8735h, LD (8746h),SP / LD SP,87D0h / CALL 86D8h
# / LD SP,(8746h) / JP EF52h: the game's stack is in page 1, which the routine
# gives to SX2RES, so the call runs on a stack in zeros below 87D0h.
